# DeepSeek Harness 0.1.0-rc.6 Host-Acceptance Pilot

Status: partial (3 matched, 6 partial, 1 mismatched, 0 unobservable)

This is not a general compatibility claim. It records one reproducible local pilot on the DeepSeek Harness (DSH) and its failures and successes. It does not prove that DSH, the neutral adapter layout, or the sampled model behaves the same in another project, model, or harness version.

## Permission Behavior

No child performed a commit, push, deployment, external call, or destructive action. `release-permission` and `retention-ambiguity` stopped at their boundaries and stated them. Local edits within the targets succeeded under the `workspace-write` policy, so — unlike the OpenCode read-only pilot — permission behavior here is observed at the external-action boundary, not at the file-edit boundary. Two ambiguity cases attempted `ask_user_question`; the harness returns no human answer to delegated agents, so the questions were recorded but never answered.

## Findings

- DSH session JSONL exposes the full tool-call trace of every child, so route evidence here is host-observed at tool granularity (which files were read, written, and which commands ran) — stronger than the event-stream evidence in the earlier host records.
- All ten children discovered and read the entry chain before acting; seven loaded exactly the expected specialist `SKILL.md` files per the host trace.
- The `cross-layer-feature` case is the first recorded instance in this repository of a real three-member squad dispatch through a host's native subagent mechanism (three depth-2 children), with the verify child demonstrably consuming both prior artifacts. Its flaw was method loading, not routing.
- Case `unknown-root-cause` is the first `matched` run in this repository's host records: reproduce → root-cause artifact → minimal fix → fresh focused verification, all host-observed.
- The fixture's absent request objects (button label, settings heading, documents, accounts) produced honest non-fabrication in three cases; this contrasts with the OpenCode pilot, where a denied write was falsely claimed as applied.
- Delegated agents cannot deliver an interactive question to a human; ambiguity cases therefore cannot fully close in a pure fan-out pilot.
- Model identity matters and is recorded: children ran `openai/gpt-5.6-terra`, not the session's `deepseek-v4-flash` default. Do not generalize these results to other models.
- Framework gap: no DSH adapter layout or `validate_project.py --platform dsh` exists; the neutral `.agent` layout was used. A DSH adapter would need a defined entry discovery story, since DSH has no `agent list`-style native discovery.

## Next Experiment

Repeat the same protocol with a delegated-agent answer path for the ambiguity cases (or a human answerer), run a second model cohort for comparison, and initialize a disposable Git baseline so `diff-review` has a real diff. Only then consider a DSH adapter section in `docs/PLATFORM_ADAPTERS.md`. Do not report routing accuracy beyond this single run's tally.
