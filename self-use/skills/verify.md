# Verify 方法（证据优先的验证）

> 用于任何"已完成 / 已修复 / 测试通过 / 可以合并 / 可以发布"的声明之前。
> 没有新鲜证据，就没有完成声明。

---

## 何时使用

✅ **必须用：**
- 说"修好了""通过了""构建成功"之前
- 提交（commit）之前
- 发起 PR / 合并 / 发布之前
- 交接给别人之前

❌ **不需要用：**
- 纯探索、纯阅读（没有改动就没有验证对象）
- 用户明确说"先别验证，我只要看方案"

---

## 证据格式（强制）

任何完成声明必须附带实际输出，不允许转述：

```
验证：[验证的是什么]
$ [完整命令]
[stdout / stderr 原文]
退出码：[0 或 非 0]
```

**规则：**
- 命令必须是可直接复制执行的完整命令（含目录、参数）
- 输出必须是真实粘贴，不允许"输出大概是这样"
- 退出码必须来自实际执行，不允许推断
- 只跑了部分测试时，明说"只跑了 X，未跑全量 Y"

---

## 验证梯度（自下而上，缺一层要说明原因）

| 层级 | 验证什么 | 典型命令 |
|------|---------|---------|
| 1. 复现用例 | **原始症状**是否消失 | 原报错命令 / 原操作步骤 |
| 2. 针对性测试 | 改动的函数/模块 | 单文件或单用例测试 |
| 3. 集成/端到端 | 跨层链路仍然通 | 接口调用、E2E 用例 |
| 4. 回归全集 | 没有弄坏别处 | 全量测试套件 |
| 5. 构建/静态检查 | 能编译、类型/格式合规 | build、typecheck、lint |
| 6. 人工烟测 | 机器测不到的真实体验 | 手动点一遍关键路径 |

**第 1 层不可跳过。** 测试全绿但原始症状还在，等于没修。

---

## 覆盖矩阵

对本次改动的每一条路径，写清"哪条验证覆盖了它"：

| 改动路径 | 覆盖它的验证 | 结果 |
|---------|-------------|------|
| [文件:行为] | [命令] | 通过 / 未覆盖 |

**未覆盖的路径必须显式列出来**，并说明风险或补测计划。空着的格子比失败更危险。

---

## 反例（这些不算验证）

❌ "应该没问题" / "逻辑上是对的"
❌ "我记得之前跑过"（不是本次改动后的新鲜证据）
❌ "我改的是 A，只跑 A 的测试就够了"（没验证没有回归）
❌ 只贴测试名不贴输出
❌ 只看 stdout 不看退出码（很多工具失败时也打印"看起来正常"的文字）
❌ 测试缓存导致的假通过（如 pytest 缓存、增量构建跳过、mock 掉了真正要验证的调用）
❌ 把 Agent 自己写的总结当作证据（总结是 claimed，命令输出才是 command-evidence）

**正例：**
```
验证：原始症状（报表保存后空白）已消失
$ npm test -- ReportSerializer.test.ts
PASS tests/ReportSerializer.test.ts
  ✓ serializes null customFields as {} (12ms)
Tests: 1 passed, 1 total
退出码：0

验证：无回归
$ npm test
Tests: 237 passed, 237 total
退出码：0
```

## 输出交接物

生成 `.idc/tasks/{task-id}/verification.md`：

```markdown
# 验证报告：{任务标题}

## 验证环境
- 目录 / 分支 / 版本：
- 时间：

## 1. 原始症状
$ [命令]
[输出]
退出码：

## 2. 针对性测试
$ [命令]
[输出]
退出码：

## 3. 回归测试
$ [命令]
[输出]
退出码：

## 覆盖矩阵
| 改动路径 | 验证 | 结果 |

## 未覆盖 / 已知缺口
- [路径] — 原因 — 风险

## 结论
[通过 / 部分通过 / 未通过] + 一句说明
```

---

## 权限门禁

验证通过不等于可以继续做有后果的动作。以下必须单独获得用户明确授权：

- `git commit` / `git push`
- 部署、发布、改生产配置
- 数据迁移、批量删除、写生产数据
- 修改 auth / billing / privacy 相关代码
- 调用付费接口

**询问格式：**
```
修复完成，验证通过（证据见上）。

下一步需要：git commit -m "fix: ..."
影响范围：[模块]

是否授权 commit？
```

---

<HARD-GATE>
在发出任何完成声明前，必须完成：

- [ ] 原始症状已被重新验证（第 1 层）
- [ ] 针对性测试有真实输出与退出码
- [ ] 回归验证已跑，或明确说明为何没跑及其风险
- [ ] 覆盖矩阵填写完整，缺口显式列出
- [ ] 生成了 verification.md 交接物
- [ ] 有后果的动作已单独获得授权

任何一项缺失，只能说"部分完成"并列出缺口，不可以说"已完成"。
</HARD-GATE>

## 时间预估

| 改动规模 | 预计时间 | 说明 |
|---------|---------|------|
| 单点修复 | 1-3 分钟 | 一个针对性测试 + 一次相关回归 |
| 多文件改动 | 5-15 分钟 | 覆盖矩阵 + 全量回归 |
| 跨层/高风险 | 20-60 分钟 | 含手工烟测、迁移演练、回滚验证 |

**如果验证比重写还慢**：说明测试资产太薄。把这次缺的测试补上，而不是跳过验证。
