# 任务卡（轻量版）

> 用于 80% 的日常任务。执行过程中逐步追加，不是预先填写完再开工。
> 文件位置：`.idc/tasks/YYYYMMDD-NNN.md`

---

## 初始内容（开工时创建）

```markdown
# [类型] 任务标题

**任务 ID**：YYYYMMDD-NNN
**开始时间**：YYYY-MM-DD HH:MM
**风险评估**：低 / 中 / 高

## 意图与范围
- 明确需求：[用户原话转成的可验证行为]
- 不在范围内：[明确排除的内容]
- 建议默认：[标注为建议的默认值]
- 开放歧义：[影响产品/权限/数据的待定项]

## 执行记录
（执行过程中逐步追加）

---
**状态**：进行中
```

**类型取值：** FIX（修复）/ FEAT（新功能）/ SEC（安全）/ REF（重构）/ OPS（运维）

**风险评估：**
- 低：局部改动，无外部契约、无数据影响
- 中：跨文件或影响单个接口/页面
- 高：数据 schema、auth、billing、隐私、不可逆操作

---

## 追加时机与内容

| 时点 | 追加内容 |
|------|---------|
| 诊断/设计完成 | 断裂点或现状数据流；交接物路径 |
| 实现完成 | 修改文件列表（含行数变化）；主要变更点 |
| 验证完成 | 命令 + 关键输出 + 退出码；未覆盖缺口 |
| 任务结束 | 结束时间、总耗时、后续项 |

---

## 完整示例

```markdown
# [FIX] API /users 返回 500

**任务 ID**：20260909-001
**开始时间**：2026-09-09 14:23
**风险评估**：中

## 意图与范围
- 明确需求：/users 正常返回用户列表
- 不在范围内：不调整分页参数
- 建议默认：无
- 开放歧义：无

## 执行记录

### 诊断阶段
- 断裂点：UserRepository.java:45
- 根因：查询返回 null 时未做防御性检查
- 详见：`.idc/tasks/20260909-001/diagnosis.md`

### 实现阶段
- 修改文件：UserRepository.java (+5 行)
- 主要变更：添加 null 检查并返回默认空列表

### 验证阶段
- 原始症状：curl /api/users 返回 200 与用户列表（退出码 0）
- 单元测试：15/15 通过（退出码 0）
- 回归：237/237 通过（退出码 0）
- 未覆盖：并发写入场景（本次未涉及）
- 详见：`.idc/tasks/20260909-001/verification.md`

---
**状态**：已完成
**结束时间**：2026-09-09 14:35
**总耗时**：12 分钟
**后续项**：为 null 场景补一个回归用例
```

---

## 规则

- 任务卡不是计划书：宁可短，也不能与真实执行不符。
- 声称完成前，卡里的"验证阶段"必须有真实命令输出，不能只写"测试通过"。
- 任务卡与代码一起提交时可以省略内容细节，但不能省略验证证据。
